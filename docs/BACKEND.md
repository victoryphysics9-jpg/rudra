# Backend deployment

1. Create Supabase project. Run `backend/schema.sql` once via SQL editor. Disable open email signups and create staff users through Authentication dashboard. Add each authorized staff UUID to `public.staff` manually. The SQL permits only authorized staff to read leads or update status/notes. No anonymous read/write policy exists.
2. Deploy `backend/functions/submit-enquiry/index.ts` as an Edge Function named `submit-enquiry`. Use Supabase CLI (initialize a project, copy function under `supabase/functions/submit-enquiry/`, link and deploy) or dashboard editor. Set `ALLOWED_ORIGINS` to comma-separated exact origins, e.g. `https://rudraearthingsystem.com,http://localhost:8000`; configure a Cloudflare Turnstile widget and secret. Supabase injects `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` into functions. Do not expose service role key. Use legacy anon key if JWT verification is enabled; otherwise follow current Supabase gateway settings and validate captcha in function. Do not disable captcha for production.
3. Edit `site/assets/config.js`: `supabaseUrl` is the project URL; `supabaseAnonKey` is the public anon key; `enquiryEndpoint` is the deployed function URL; `turnstileSiteKey` is the public widget sitekey. Never add secrets. Redeploy frontend. Use a real domain in Turnstile allowed hostnames.
4. Test valid enquiry, invalid payload, replayed captcha, unauthorized read, staff login, status/notes update, CSV export and sign-out. Confirm lead record persists, no anonymous access and no duplicate submission. Add server-side rate limiting, logs/alerts, email notification, retention/backup and security review before paid campaigns. The source includes captcha and validation but not a dedicated rate-limit store.
5. Public RFQ sends only an accepted `generate_lead` event to an optional existing `window.dataLayer`. GTM/GA4/Google Ads tags are not installed. Configure tags and consent with client-approved privacy policy; do not transmit contact details to ad platforms. Test conversion event only after acknowledged enquiry. Campaign IDs are captured in session storage and passed to backend on submission.
6. Admin is an enquiry pipeline, not yet a full CMS. Product editing requires editing `src/products.json` and rebuilding. No quote PDF or email send service is implemented.
